外部 MCP 让 TwiCC 之外的智能体可以使用你的实例。例如，你可以连接一个 MCP 客户端来查看项目、创建会话或发送带图片的消息。

TwiCC 仍然是单用户应用。每个连接到你实例的连接都需要你批准。你无需为连接的客户端创建另一个用户账号。

### 内部 MCP 与外部 MCP

在 TwiCC 内部运行的智能体已经拥有内部 MCP 连接。它们不需要此设置，也不需要 OAuth 批准。禁用外部 MCP 不影响它们的内部访问。

外部客户端通过专用的公共地址连接。在你批准后，它们通过 OAuth 获得访问权限。

### 连接可以做什么

已批准的连接对外部 MCP 工具拥有完全访问权限。它可以读取和更改你的 TwiCC 数据、管理项目和会话、发送消息以及管理分享。没有按连接区分的权限选项。

批准针对的是连接，而不是每次工具调用。客户端创建的每条消息或每个会话都无需再经 TwiCC 批准。

外部客户端不是 TwiCC 会话。它不能使用 `whoami`、`self` 或 `parent` 来识别调用方会话。在工具需要会话的地方，它必须提供明确的会话 ID。与会话相关的操作需要该上下文；无法从外部连接推断。

### 附件

外部客户端可以在 `attach` 中使用 base64 data URI 附加其所在机器上的文件：`data:<mime>;name=<percent-encoded file name>;base64,<data>`。`name=` 用于保留文件名。每条命令的内联数据限制为 50 MiB。更大的文件请放到文件存储服务上，并在消息文本中传递其 URL，或传递 TwiCC 主机上已有文件的绝对路径。对等消息会内联发送所有文件，因此那里只能使用 URL。

### 连接之前

使用密码启动 TwiCC。没有密码就无法启用外部 MCP。如果你在没有密码的情况下重启 TwiCC，TwiCC 会禁用外部 MCP 并保留现有授权。专用 URL 会保持保存状态。恢复密码后，请再次启用外部 MCP。客户端可以使用现有凭据继续工作，但仍受其正常过期时间约束。之前被撤销的授权保持撤销状态。

要设置密码，请运行：

```
<twicc> password set
```

其中 `<twicc>` 替换为你平时启动 TwiCC 的方式。设置密码后请重启 TwiCC。

打开 **设置 → 外部 MCP**。输入你的 **专用 MCP URL**，然后选择 **应用**。输入 HTTPS 源，例如 `https://mcp.example.com`，不要包含 `/mcp`。然后启用 **外部 MCP 访问**。

请使用专用主机名，与你的外部、分享和对等实例地址不同。此主机名只提供 MCP 及其 OAuth 端点，不提供 TwiCC 界面、文件或其他应用路由。

该地址必须能被客户端访问。MCP 调用是机器之间的调用。如果你平时使用的隧道要求访问者通过邮箱、SSO 或其他交互式检查登录，请不要将其用于 MCP。客户端无法完成这类检查。

请创建一个没有这类门禁的单独隧道地址，并将其指向你的 TwiCC 服务器。在你平时使用的 TwiCC 地址上保持保护。TwiCC 通过 OAuth 和你的连接批准来保护 MCP 地址。

一般的隧道和密码设置请参见 [从任何地方访问 TwiCC](help/external-url)。

### 连接客户端

从设置中复制 **MCP URL**，并将其填入客户端的远程 MCP 配置中。此地址包含 `/mcp`，例如 `https://mcp.example.com/mcp`。

请使用支持 OAuth 远程 MCP 的客户端。具体的设置选项取决于客户端。TwiCC 通过标准的 MCP 发现端点提供授权信息。

桌面客户端可以在 `http://127.0.0.1` 或 `http://[::1]` 上接收浏览器回调，并且每次连接可以使用不同的可用端口。注册的地址、路径和查询仍必须匹配。此端口例外不适用于远程 HTTPS 回调或主机名 `localhost`。

从客户端发起连接。它会打开一个带有验证码的授权页面。请保持该页面打开，直到连接完成。

TwiCC 会在你已登录的设备上显示一个持续存在的连接请求通知。选择 **审查**，然后输入发起连接的浏览器中显示的验证码。验证码会将你的批准与你发起的请求关联起来。

你可以在另一台设备上批准。发起连接的浏览器仍会完成 OAuth 流程。请求处理完成后，通知会从你的其他设备上消失。

在选择 **授权** 之前请先查看客户端详情。如果请求不是你发起的，请选择 **拒绝**。请求会在十分钟后过期；过期后请从客户端重新发起。

### 名称与消息标头

你可以为每个连接设置一个可选名称，例如 **ChatGPT** 或 **桌面助手**。之后可以在连接详情中更改。

审查时，名称字段会预填客户端自己声明的名称。在授权前请确认、修改或清除它。TwiCC 只使用你批准的名称：客户端无法在你的对话中自行命名。

通过该连接发送的消息会带有类似 **Message via ChatGPT** 的标头。没有名称时，标头显示 **Message via external MCP**。该标头标识的是连接，而不是另一个 TwiCC 会话。

详情中的 **客户端 ID** 是技术标识符。它不是访问 Token，也不是验证码。批准请求时无需复制它。

### 管理连接

打开 **设置 → 外部 MCP → 管理连接**。列表在有条目时会显示三个部分：

- **待处理请求**——等待你决定的请求；
- **活跃**——已批准的连接，包括仍在完成 OAuth 的连接；
- **已撤销**——不再拥有访问权限的连接。

选择 **审查** 查看请求，或选择 **详情** 查看现有连接。如果详情是从列表中打开的，关闭后会返回列表。从通知打开的请求会直接进入其详情；关闭该对话框不会打开列表。

多个客户端可以各自独立连接。撤销一个连接不会撤销其他连接。

### 撤销访问

选择 **撤销** 可阻止某个连接继续进行 MCP 调用。其现有凭据将不再授予访问权限。撤销不会撤回已完成的工作，也不会停止该客户端之前启动的会话。

被撤销的连接会保留在列表中。要重新连接，请从客户端发起新连接并批准其新请求。

更改专用 MCP URL 或禁用外部访问会撤销现有连接。请在客户端中配置新地址并重新连接。

### 防范 OAuth 滥用

TwiCC 会按客户端和按网络来源限制新的 OAuth 请求。一个客户端最多可以有三个待处理请求；一个来源最多可以有十个。一个来源最多可以保留二十个从未获得授权的已注册客户端。

多次准入拒绝或异常偏高的准入流量会触发对新注册和授权请求的十分钟暂停。所有者会收到 **疑似 OAuth 滥用** 通知。设置和连接管理器会显示原因、最近的计数以及剩余的暂停时间。

暂停期间，现有 MCP 连接、Token 续期、撤销以及正在进行的授权请求仍然可用。暂停会自动结束。警报会一直保留，直到你关闭它。高流量只是疑似滥用，并不能证明受到攻击。多个客户端可能共享同一个网络来源。

选择 **暂停所有外部访问** 可停止所有新的外部 MCP 和 OAuth 请求，而不撤销现有授权。正在执行的请求可能会完成。要恢复，请在设置中重新启用外部访问。这种手动暂停在重启后仍然有效。

流量计数、警报和自动暂停会在 TwiCC 重启时重置。注册和待处理请求的配额会保持存储。在暂停期间，正常的 Token 和请求过期规则依然适用。

速率限制使用 ASGI 服务器提供的客户端地址。代理必须传递真实的客户端地址，并且被服务器信任；TwiCC 本身从不信任任意的转发标头。同一 /64 内的 IPv6 地址共享一个来源配额。只存储带密钥的来源哈希，而不存储 IP 地址。

### 如果连接未能完成

请检查外部 MCP 是否已启用，以及客户端是否使用了复制的 URL（包括 `/mcp`）。检查专用主机名是否能访问到此 TwiCC 实例，并且没有显示隧道提供商的登录页面。

批准时请保持发起连接的浏览器处于打开状态。如果列表显示 **连接中**，说明批准已成功，但客户端尚未完成 OAuth。如果请求过期，请从客户端发起新的连接。

### 批量命令

使用 `batch_read` 在一次 MCP 调用中收集多个独立的读取操作。默认最多同时运行四条命令。将 `mode` 设为 `sequential` 可按顺序运行。对于有顺序要求的命令（包括更改操作），请使用 `batch`。它始终按顺序运行。在 TwiCC 内部运行的智能体也可以使用相同的工具。

请先了解每条命令的 schema。提供其正常的 MCP 名称和参数：

```json
{
  "calls": [
    {"id": "recent", "name": "sessions", "arguments": {"limit": 5}},
    {"id": "projects", "name": "projects", "arguments": {}}
  ]
}
```

每个调用都需要唯一的 `id`、命令 `name` 以及 `arguments` 对象。TwiCC 会在任何命令开始前验证整个批次。只要有一个调用无效，整个批次就会被拒绝，其他命令也不会执行。每条命令仍会进行正常的权限检查。外部调用仍需提供明确的会话 ID。

结果会按输入顺序一起返回。每条记录包含其 ID、执行状态以及命令正常的 `{exit_code, result, error}` 响应。请检查汇总的 `ok` 字段以及每条记录。已完成的批次中可能包含失败或被跳过的命令。命令也可能执行成功但其较大的响应被省略（`response_omitted: true`）；这种情况下汇总的 `ok` 为 false。

`batch` 默认在发生执行错误后停止。将 `on_error` 设为 `continue` 可尝试执行剩余命令。`batch_read` 默认为 `continue`。并行执行需要 `continue`；`stop` 请使用顺序模式。输出被省略不会停止后续命令。已完成的更改会保持生效：没有回滚、自动重试，也不会将结果传递到后续参数中。不支持嵌套批次。

一个批次最多接受 20 条命令。两种 MCP 连接在整个实例范围内共享最多四个活跃批次和八条活跃批次命令的限制。超出的批次会收到 `server_busy`。单独的工具调用不受此批次准入限制。整个请求（包括附件）限制为 72 MiB；每条命令最多接受 50 MiB 的内联附件数据（更大的文件请参见上方的“附件”）。超过 384 KiB 的命令响应会被明确省略。合并后的工具结果（包括文本和结构化数据）保持在 16 MiB 以下。客户端的限制可能更小。

请保持批次简短，并对长时间等待使用单独的调用。现有命令超时仍然适用；没有额外的批次超时。长时间等待可能占满所有批次容量，即使客户端已取消请求。取消或超时并不能证明写入已停止。在重试结果不确定的写入之前，请先检查受影响的资源。批次 ID 用于诊断时标识调用；它们并不能防止重复执行。

TwiCC 会在每条命令开始前检查外部授权。过期、撤销或禁用外部访问会停止剩余命令。如果 TwiCC 无法验证授权，也会停止它们。已开始的命令可以完成，其已收集的结果会被保留。
