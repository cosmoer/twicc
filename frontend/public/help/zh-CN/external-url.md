**外部地址** 是你从各个设备访问 *此* TwiCC 实例所用的地址。TwiCC 还会用它构建指回你的会话的链接。这样，外部通知就能打开正确的对话，而不是一个无法访问的 `localhost` 地址。

### 它有什么用

- 在 TwiCC 持续运行于家中机器上的同时，从 **手机或另一台电脑** 打开会话。
- 它还会被嵌入到 **外部通知**（Apprise）中：推送的提醒可以直接链接到相关会话。

留空时，TwiCC 只是省略这些链接——其他功能都不受影响。

### 为什么需要隧道

TwiCC 作为本地进程运行，因此 `http://localhost:…` 只在运行它的机器上有意义。要从其他地方访问它，你需要通过 **隧道** 将它暴露出去：隧道服务会为你的本地实例提供一个稳定的公共地址，并将流量转发回来。这个公共地址正是你要填入外部地址的内容。几个常用的选项：

- **Cloudflare Tunnel**（`cloudflared`）——带有稳定主机名的命名隧道。
- **Tailscale**——在你自己的设备之间组建私有 mesh VPN，可选择公开暴露（Funnel）。
- **ngrok**——为本地端口快速生成公共 URL。

### 保护你的隧道

隧道可能让你的实例能够从公共互联网访问，因此请认真对待。每个提供商都提供了加固手段——请使用它们：

- **Cloudflare Tunnel** → 在前面加上 **Cloudflare Access**（邮箱一次性 PIN、Google/GitHub SSO），并添加 IP 规则或 WAF。
- **Tailscale** → 将其保留在你的 **私有 tailnet** 中，只让你自己的设备访问（除非确实需要，否则避免使用公开的 Funnel）；用设备 ACL 进一步收紧。
- **ngrok** → 启用其内置的 **Basic Auth**、**OAuth**（Google、GitHub…）或 IP 白名单。

### TwiCC 自己的密码最重要

最重要的一点：**除非你设置了密码，否则 TwiCC 会拒绝所有非本地连接。** 因此，只有在你运行 `twicc password set` 之后，外部地址才会真正生效——这个密码是你的主要保护。

（隧道提供商的保护位于其 *之上*——是密码之外的第二层保护——但它依然重要：它能让不需要的流量在到达登录界面之前就完全远离 TwiCC。）
