TwiCC 可以 **朗读聊天消息**。在 **设置 → 文字转语音** 中选择一个配置，测试它，确认你听到了，然后激活它：消息上就会出现一个扬声器按钮。

配置有两种：

- **OpenRouter**：[OpenRouter](help/openrouter) 的语音模型及其音色。
- **脚本**：你自己的 shell 命令，用于将文本转换为音频。

## 朗读新的时间线消息

**时间线旁边的扬声器按钮** 会在新的助手消息到达时将其朗读出来。范围、队列、摘要，以及离开页面或应用时会发生什么，都在单独的页面中说明：[时间线朗读](help/timeline-speech)。

## 总结消息或选中内容

在聊天或时间线消息视图中，对符合条件的助手消息使用 **总结**。阈值按完整的逻辑消息计算，包括其中的代码和文本块。不包括嵌入的产物内容和控制标记。摘要的目标长度约为原文的三分之一，最多 140 个词。

消息摘要会被保存。当来源和模型策略一致时，聊天、时间线视图和自动收听共享同一结果。自动准备也会保存成功的摘要。旧策略的结果仍然可用。重新生成只有在成功后才会替换结果。

使用 **显示摘要** 在原文和摘要之间切换。复制和 **朗读** 使用当前视图。朗读聊天原文时保持其原始的块范围。朗读时间线原文时使用组装好的时间线快照。手动朗读会打断自动朗读，并且与自动摘要开关无关。通常的项目和会话播报永远不会标明这是摘要。

选中文本后，在选中操作中使用 **总结** 可生成临时摘要。其对话框支持复制、朗读、重试、取消和关闭。关闭对话框会释放其生成任务并停止对应的朗读。选中内容的摘要和设置中的测试永远不会被保存为消息摘要。

摘要文本会以流式方式显示。朗读会从已有的摘要部分开始，无需再次调用文本调整。如果朗读开始后生成失败，播放会停止并显示错误。TwiCC 不会改为播放原文，也不会保存部分摘要。

### 摘要模型

在 **设置 → 摘要** 中选择 **自动**、**Claude Haiku 5.5**、**GPT-6 Luna** 或 **OpenRouter**。自动会选择一个已启用且正在运行的智能体，先是 Claude，然后是 Codex。所选智能体不可用时，会改用另一个智能体。

OpenRouter 需要其密钥：参见 [OpenRouter](help/openrouter)。没有密钥时，或原文超过 **60,000 个字符** 时，TwiCC 会选择一个已启用的智能体。它会保留完整的原文。如果 OpenRouter 在摘要朗读开始前失败，已启用的智能体可以替换其临时文本。没有可用模型时，总结会显示错误。自动时间线开关不会禁用手动摘要。

## 测试、确认、激活

**测试** 会使用该配置朗读测试文本，然后询问 **“你听清楚了吗？”**。回答 **是** 即可验证该配置。只有经过验证的配置才能被激活，而消息使用的就是当前激活的配置。

更改发声相关的设置（模型、音色、格式、命令…）会使验证失效：请重新测试配置。

## OpenRouter 配置

它们需要 OpenRouter 密钥。[OpenRouter](help/openrouter) 中说明了如何设置。

显示的价格是 OpenRouter 的标价。测试之后，配置会显示测试朗读的实际费用。

## 长消息

长消息会 **分段** 朗读，一段接一段，合成一个音频。每一段都在播放需要时生成，大约提前一分钟：声音很快就会开始，停止后也不会生成（也不会为之付费）剩余部分。段与段之间的衔接可能听得出来。

## 朗读选中内容

在聊天或文件查看器中选中文本：浮动组件会在评论和复制按钮旁边显示 **朗读按钮**（扬声器图标）。它不会出现在终端、浏览器窗格或元素卡片中。与消息的扬声器按钮一样，它只在语音服务可用时显示。

- 该按钮会使用当前激活的配置朗读选中的文本。其标题为“朗读”。
- 朗读期间，同一个按钮会变成 **停止图标**（标题为“停止朗读”），并保持可见。点击它可取消请求或停止声音。
- 浮动组件关闭后声音仍会继续。与消息一样，可以通过侧栏的朗读指示器停止它。
- 去除格式后没有可朗读内容的文本会被拒绝，与消息相同。

## 调整文本

当文本不简单时，一个小模型可以在朗读前 **将文本改写得更适合收听**：表格变成句子，列表变成口头列举，代码块变成简短描述；哈希值、长路径和 Markdown 语法会被去掉。内容和语言保持不变。**简单文本会直接朗读**，只去除 Markdown 标记而不使用模型：声音开始得更早，也无需为改写付费。Markdown 链接会读出其文字。

配置的测试从不使用直接朗读：只要模型能够运行，就会经过模型，以便展示调整效果，其最近一次测试运行会显示调整后的文本。选择 **关闭**，或没有可用模型时，会按原文朗读。

例如，以下文本 **不简单**，会经过模型处理：

- 表格、代码和类似代码的文本（任何包含代码符号的内容，例如 `$`、`=`、`|` 或花括号、`snake_case` 名称、`#123`），以及 HTML；
- 地址、路径、哈希值和长数字；
- 长列表：超过五项、条目较长或包含子列表；
- 聊天中包含换行或制表符的选中内容，以及文件查看器中的任何选中内容。

当规则无法确定地识别一段文本时，由模型决定。

在 **设置 → 文字转语音** 顶部的 **调整文本以便朗读** 中选择模型：**Claude Haiku 5.5**、**GPT-6 Luna**、**OpenRouter**，或 **关闭**（按原文朗读所有文本）。未做选择时，TwiCC 会使用 Claude，否则使用 Codex。如果 Claude 或 Codex 模型的提供方被禁用，会改用另一个智能体，重新启用该提供方后你的选择会恢复。

Claude Haiku 5.5 和 GPT-6 Luna 使用你的 Claude 或 Codex 订阅运行。**OpenRouter** 会调用 [OpenRouter](help/openrouter) 上的一个快速模型。与 OpenRouter 配置一样，它需要 OpenRouter 密钥。设置密钥后，即使没有任何提供方在运行，它也能调整文本。没有密钥时，会改用默认选项，在设置密钥并重启 TwiCC 后你的选择会恢复。

如果 OpenRouter 在朗读开始前失败，第一个能运行的智能体（Claude，否则 Codex）会调整文本。如果没有模型能运行、文本过长，或者模型在朗读开始前失败（对于 OpenRouter：如果该智能体也失败，或没有提供方在运行），文本会 **按原文** 朗读。如果模型在之后失败，朗读会停止并显示错误。

配置的最近一次测试运行会显示调整文本所用的模型，或每个失败的模型及其原因：密钥错误或 OpenRouter 账户余额为空都会显示在那里。测试的费用只包括语音费用：不包括 OpenRouter 的文本调整费用。

## 脚本配置

TwiCC 会在你的 shell 中以非交互式登录 shell 的方式、在你的主目录下运行 **命令**，并将文本写入其 **标准输入**。命令将音频写入其 **标准输出**，并以状态 0 退出。文本永远不会出现在命令行中。

| 输出 | 命令写出的内容 | 声音开始的时机 |
|---|---|---|
| **音频流** | 音频，边生成边写出 | 收到第一个字节时 |
| **完整音频** | 音频，在结束时写出 | 运行结束时 |
| **文件路径** | 一个绝对路径，每次运行指向一个新文件 | 运行结束时 |

| 格式 | 命令提供的内容 |
|---|---|
| **MP3** | MP3 |
| **WAV** | 16 位 PCM WAV（边写边输出、大小未知的 WAV 也可以） |
| **PCM** | 原始 16 位小端 PCM：需提供其采样率和声道数 |

**每次运行的最大字符数**：留空时，整个文本在一次运行中处理。否则文本会被拆分为不超过此大小的若干部分，每部分运行一次。使用 **完整音频** 或 **文件路径** 时请设置此项：这样声音会在第一部分之后开始，而不是在整个文本之后。

**朗读后删除文件**（仅限文件路径，默认开启）：TwiCC 在读取文件且运行成功后会删除该文件。它只检查路径是否为普通文件，而不检查文件位置：请确保命令返回的是它自己新建的文件。运行失败时会保留其文件。

### 失败时

- 以非零状态退出的命令会显示其 **错误输出的最后一行**。
- 否则 TwiCC 会说明问题所在：输出不是所选格式、没有音频、路径不是单个绝对路径…
- **标准输出中不能打印任何其他内容**：来自 shell 配置文件的消息或进度行都会破坏音频。
- `~/.bashrc` 或 `~/.zshrc` 中设置的内容通常不可用（别名、`PATH` 追加项）：请使用完整路径，或使用自行设置所需环境的脚本。

### 须知

- 停止会结束整个命令，包括管道。
- 多次朗读可能同时运行该命令（一次测试和一条消息，或两台设备）。
- 音频流在首次输出音频后一分钟内没有任何输出时会被停止。单次朗读的音频限制为 512 MB。
- TwiCC 只能看到命令行：编辑了命令所运行的脚本后，请重新测试配置（否则消息可能会播放缓存的音频，缓存最长 10 分钟）。

### 示例

一个忽略文本的测试音（**音频流**，**WAV**）：

```
ffmpeg -nostdin -loglevel error -f lavfi -i sine=frequency=440:duration=3 -ac 1 -ar 22050 -f wav -
```

[eSpeak NG](https://github.com/espeak-ng/espeak-ng)（**音频流**，**WAV**）：

```
espeak-ng --stdin --stdout -v en
```

同样的命令，通过文件输出（**文件路径**，**WAV**）：

```
f=$(mktemp) && espeak-ng --stdin -v en -w "$f" && echo "$f"
```

[Piper](https://github.com/rhasspy/piper)（**音频流**，**PCM**，采样率为该音色的采样率，通常为 22050 Hz，1 个声道）：

```
piper --model ~/voices/en_US-lessac-medium.onnx --output-raw
```

## 已知限制

- 在 iPhone 或 iPad 上（以及 Safari 中的 MP3），音频会先完整下载再播放：声音开始得更晚。
- 在 Android 上，PCM（或 WAV）格式的长时间朗读可能会在锁屏后不久停止：浏览器会冻结页面。
