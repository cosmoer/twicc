工作树是同一仓库的第二份工作副本，检出到 **不同的分支**，位于 **独立的文件夹** 中——与仓库共享历史记录。它让你（或智能体）可以在功能分支上工作，而不影响你的主检出。

在 TwiCC 中，工作树会显示为 **独立的** [项目](help/projects)，并自动链接到主仓库。它的会话、成本和活动会 **汇总到父项目的视图中**，让你能看到全貌，而不是各自孤立。

### 工作树创建在哪里

**工作树目录** 设置决定 TwiCC 在哪里创建新的工作树，并在你创建工作树时预填路径。全局设置是一个 **模板**，其中的占位符会按项目解析——`{git_root}`（项目的 Git 根目录）、`{project_name}`（项目名称，未命名时为文件夹名）以及 `{project_basedir}`（项目的文件夹名）——因此 `{git_root}/.worktrees` 会把工作树放在各自的仓库中，而 `/home/me/worktrees/{project_name}` 则会把它们集中在一个位置。每个项目都可以用自己的绝对路径覆盖它——全局设置在“设置”中，项目设置在其编辑对话框中。

### 创建工作树

你会在新建会话的同时创建工作树。在 **新建会话** 菜单中，每个项目行的右侧都有一个工作树按钮——带 **+** 的分支图标；点击它即可打开工作树对话框。（该按钮只对 Git 仓库项目显示。）

在对话框中：

- **新建工作树**——TwiCC 会在所选位置创建工作树及其分支。
- **现有工作树**——接管磁盘上已存在但 TwiCC 尚不知道的工作树（“现有工作树”标签页）。

无论哪种方式，你都可以立即在新工作树中开始一个草稿会话。

### 清理

工作树会一直显示在项目选择器和新建会话菜单中，直到你将其 **归档**——可以在其编辑对话框中操作，或使用侧边栏顶部项目选择器中该工作树的 **⋮** 菜单（归档会隐藏它而不删除任何内容）。不过这只是把它从 TwiCC 中整理掉：真正结束工作树——合并分支并从磁盘上删除它——需要你或你的智能体来完成；TwiCC 不会这样做。
